# CreditVintage 0.5.0

This version adds a model-free route to inspect which decision-time inputs
changed, before historical or current outcome labels are available.

## New commands

- `monitor-features` compares utilization, debt-to-income, prior delinquency
  count, principal in cents and segment composition. It accepts only the two
  application/feature CSV paths and the existing calendar configuration.
- Numeric inputs use empirical KS distance; segments use total variation.
  Whole-population comparisons require 20 applications per population; small
  monthly slices retain counts with no distance estimate. There are no
  significance tests or automatic decision thresholds.
- `verify-feature-monitor` rebuilds snapshots, cumulative/category counts,
  distances, summaries and HTML from retained application/feature events. A
  rehashed false distance fails replay. Evidence contains no performance records
  or model scores. Existing report destinations are not overwritten.

Read the [method, two-CSV example and limitations](../FEATURE_MONITORING.md).
The report is restricted to the existing strict event schema; missing-feature
rates and arbitrary-column drift are not implemented. Input distribution changes
do not establish model deterioration or real credit risk.

## Install and check

Use Python 3.12+ in a virtual environment:

```text
python -m pip install --upgrade https://github.com/dev-belly/CreditVintage/releases/download/v0.5.0/creditvintage_research-0.5.0-py3-none-any.whl
python -c "from importlib.metadata import version; print(version('creditvintage-research'))"
python -m creditvintage monitor-features --as-of 2024-10-01 --out outputs/feature-monitor-050
python -m creditvintage verify-feature-monitor outputs/feature-monitor-050
```

The version check prints `0.5.0`. The generated example has 480 reference and
320 visible current applications. Choose a new output directory when repeating
the command. On Windows, `.\.venv\Scripts\python.exe` can replace `python`.

## Compatibility and distribution checks

Existing input schemas, evaluation protocols, numerical pins, score PSI,
review evidence and snapshot time/maturity rules retain their contracts.
The two-table loader shares the existing strict CSV parser with the original
three-table loader. Feature-monitoring artifacts have a separate versioned
schema, so old score-monitor reports use the same original verifier.

The installed-wheel checker runs the new two-CSV route outside the checkout
while the performance file is absent, verifies all five inputs and population
counts, and confirms that rehashing an incorrect distance fails. Tests compare
numeric distances with SciPy and exact hand calculations, including constant
populations and principal differences above binary64 integer precision.

Publication waits for all main CI jobs, including Linux/Windows installed-wheel
checks and cross-runtime card-data replay. The publisher retains the exact wheel
and source archive from successful CI, along with installed-check evidence,
an exact-commit manifest and SHA-256 checksums. Prior releases are retained.
