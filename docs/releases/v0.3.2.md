# CreditVintage 0.3.2

This patch delivers consistent calendar-date validation in the installed package.
Earlier release tags and assets are preserved.

## Changes from 0.3.1

- All event CSV date fields, cohort JSON and `monitor --as-of` now require the
  documented `YYYY-MM-DD` form. Compact dates such as `20241001` and ISO week
  dates such as `2024-W40-2` are rejected instead of silently normalized.
  Use `2024-10-01`. Timestamps, surrounding spaces and impossible dates are also
  invalid. Cohort JSON was already strict in earlier versions.
- `check-inputs` returns `value_type` issues with file, physical CSV line and
  column. It continues checking the other files, marks dependent checks as
  `blocked` and returns exit code 2 without training or modifying inputs.
  Event commands reject these dates before creating a report. Invalid
  `--as-of` arguments use the ordinary CLI argument-error path.
- Evaluation, monitoring and benchmark verifiers enforce the same format in
  saved evidence, including when a file's manifest digest has been refreshed.
- Clean installed-package CI checks rejection of an alternate CSV date and an
  ISO week monitoring cutoff, alongside the existing complete offline workflows.

Commands, field names, model protocol, dependency pins and numerical tolerances
are unchanged. Existing reports generated with canonical dates remain verifiable.
There is no model migration. Correct alternate dates in source inputs before
rerunning evaluation; do not rewrite saved evidence or hashes to bypass checks.
This validates input format, not source authenticity or future credit performance.

## Install or upgrade

In a Python 3.12+ virtual environment, install the exact release wheel:

```text
python -m pip install --upgrade https://github.com/dev-belly/CreditVintage/releases/download/v0.3.2/creditvintage_research-0.3.2-py3-none-any.whl
python -c "from importlib.metadata import version; print(version('creditvintage-research'))"
python -m creditvintage init-inputs --out inputs/check-0.3.2
python -m creditvintage check-inputs inputs/check-0.3.2
```

The version check prints `0.3.2`. The synthetic starter contains 480 applications;
its checker returns `ready_for_evaluation` with `model_fitted: false`. Choose a
new input directory each time. On Windows use `.\.venv\Scripts\python.exe` for an
environment named `.venv`; on Linux/macOS use `.venv/bin/python`.

Publication uses the exact source archive and wheel retained by successful main
CI after clean installation and cross-runtime refitting. `release-manifest.json`
binds the version, commit and file digests; `CHECKSUMS.sha256` also covers the
manifest. The installed-check JSON records the actual replay results. Existing
release assets are never replaced.
