# CreditVintage 0.7.0

Explicit user policies now check decision-time feature coverage, extending the
v0.6.0 diagnostic without changing its schema or strict scoring.

## Added commands

- `init-feature-policy --out coverage-policy.json`: write an editable example.
- `check-feature-quality QUALITY --policy coverage-policy.json --out CHECK`:
  retain overall/monthly conditions, all results, the complete source diagnostic
  and HTML/CSV/JSON evidence. Exit 0 means every rule passes; 3 means failed or
  insufficient with a report retained; 2 means invalid inputs or output errors.
- `verify-feature-check CHECK`: replay events and rules. A consistent failed
  check returns 0 with `policy_status: fail`. An optional independently saved
  `--expected-policy-sha256` detects replacement of approved rules.

No outcomes or fitting are needed. Empty/small groups cannot silently pass.
Conditions compare exact counts to decimal strings, not rounded display rates.
Only named rules are checked: a tolerant or partial policy pass does not establish
scoring readiness, source authenticity or model quality.

## Install and run

Python 3.12+ in a virtual environment:

```text
python -m pip install --upgrade https://github.com/dev-belly/CreditVintage/releases/download/v0.7.0/creditvintage_research-0.7.0-py3-none-any.whl
python -c "from importlib.metadata import version; print(version('creditvintage-research'))"
python -m creditvintage monitor-feature-quality --as-of 2024-10-01 --out outputs/quality-070
python -m creditvintage init-feature-policy --out coverage-policy-070.json
python -m creditvintage check-feature-quality outputs/quality-070 --policy coverage-policy-070.json --out outputs/check-070
python -m creditvintage verify-feature-check outputs/check-070
```

Version prints `0.7.0`. The check deliberately exits **3**: three rules fail
(318/320, 319/320 and 319/320 against full coverage). Run verification separately;
it succeeds and retains policy failure. Open `outputs/check-070/index.html`.
Use new destinations on repeat. [Policy contract and trust limits](../FEATURE_POLICY.md).

## Compatibility and release evidence

Existing quality, distribution, evaluation and score-monitoring contracts are
unchanged. Missing inputs still block strict scoring/distribution. No numerical
pins, model protocols or old artifact formats change; original feature-monitor
bytes match the public v0.5.0 fixture. No generic rules or notifications are added.

Installed CI retains the exact wheel and source archive. The publisher waits
for all main CI, including Linux/Windows installation and cross-runtime refitting,
verifies commit/version/digests and publishes five assets. Prior releases remain.
