# CreditVintage 0.3.1

This patch delivers the CSV-header fix and explicit code licensing in an
installable release. Existing 0.3.0 tags and assets remain unchanged.

## Changes from 0.3.0

- `check-inputs` now catches an unterminated quoted CSV header in any of the
  three input tables. It returns `invalid_inputs` JSON on stdout, a
  `csv_quoting` issue at the physical end line of the malformed header and exit
  code 2, and continues checking the other input files. A single-line broken
  header points to line 1; a multi-line header points to its last physical line.
  Version 0.3.0 instead raises a CSV parsing error for
  this case. The checker still does not fit a model or modify inputs.
- Project code is explicitly MIT licensed. Both original UCI dataset source
  notices and their CC BY 4.0 terms are retained. The wheel and source archive
  include the MIT license and both notices; their combined distribution
  metadata reads `MIT AND CC-BY-4.0`.
- Building from source now requires setuptools 77 or later to support that
  license metadata. This is a build requirement; numerical runtime dependency
  versions have not changed.

No commands or input fields have been renamed. There is no input-schema or
model migration from 0.3.0. Evaluation rules, frozen data, numerical dependency
pins and report verification tolerances are unchanged. The existing research
limitations still apply: synthetic event data and historical random-split
public benchmarks do not establish a deployable credit policy.

## Install or upgrade

In a Python 3.12+ virtual environment, install the exact release wheel:

```text
python -m pip install --upgrade https://github.com/dev-belly/CreditVintage/releases/download/v0.3.1/creditvintage_research-0.3.1-py3-none-any.whl
python -c "from importlib.metadata import version; print(version('creditvintage-research'))"
python -m creditvintage init-inputs --out inputs/check-0.3.1
python -m creditvintage check-inputs inputs/check-0.3.1
```

On Windows, replace `python` with `.\.venv\Scripts\python.exe` when using an
environment named `.venv`. Create it first with `python -m venv .venv` if needed.
On Linux/macOS use `.venv/bin/python` for the same environment.

The version check prints `0.3.1`; the checker returns
`status: ready_for_evaluation` and `model_fitted: false`. The starter contains
480 explicitly synthetic applications. Choose a new output directory on each
run because the starter never overwrites an existing path.

Release assets come from the successful main CI run, after clean wheel
installation, complete offline replay and cross-runtime card-data refitting.
`release-manifest.json` records the exact commit, version and file digests;
`CHECKSUMS.sha256` covers the wheel, source archive and accompanying evidence.
