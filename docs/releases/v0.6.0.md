# CreditVintage 0.6.0

This version adds decision-time feature coverage and visible-delay diagnostics,
complementing v0.5.0 input-distribution monitoring.

## New workflow

`monitor-feature-quality` reads only application and feature-event CSVs, with no
outcome file or model fitting. Every expected feature slot stays in its cohort
denominator. The report distinguishes available inputs, visible late arrivals,
post-decision observations and still-unseen records; future records cannot
explain a gap before they become visible. It retains monthly counts and timing,
including small or empty populations, without imputation or automatic thresholds.

`verify-feature-quality` rebuilds the report from retained events and rejects
rehashed false coverage. Existing output destinations are refused. The built-in
example deliberately injects four unavailable slots: 480 reference, 320 current,
316 complete current and 160 future current applications at the default cutoff.

## Install and check

Python 3.12+ in a virtual environment:

```text
python -m pip install --upgrade https://github.com/dev-belly/CreditVintage/releases/download/v0.6.0/creditvintage_research-0.6.0-py3-none-any.whl
python -c "from importlib.metadata import version; print(version('creditvintage-research'))"
python -m creditvintage monitor-feature-quality --as-of 2024-10-01 --out outputs/feature-quality-060
python -m creditvintage verify-feature-quality outputs/feature-quality-060
```

The version check prints `0.6.0`. Open the generated `index.html`.
[Method, exact reason definitions and two-CSV intake](../FEATURE_QUALITY.md).
Use a new output directory for another run.

## Compatibility and validation boundaries

Strict scoring/distribution paths still reject missing decision-time features.
Malformed values, duplicate identities/revisions and unknown references still
fail input validation. A successfully created or verified diagnostic can report
incomplete coverage; it does not certify scoring readiness. The new route
measures event coverage, not raw-column nullness or all forms of data quality.

The event index/decision selector is shared with strict snapshots. The canonical
two-table codec is shared with the feature-distribution report. A frozen manifest
generated by the public v0.5.0 wheel requires byte-identical old feature artifacts.
Existing scoring, numerical pins, model/calibration protocols, labels, PSI and
saved reports retain their contracts.

The installed-package checker runs healthy and incomplete two-CSV inputs while
the performance file is absent, verifies the unchanged strict missing-feature
gate, and rejects rehashed false coverage. Tests cover exact denominators,
empty/small groups, first-arrival delay, future-record exclusion, late corrections
and the independent v0.5.0 artifact fixture. Source archives include that fixture.

The publisher waits for the complete main CI, including Linux/Windows installation
and cross-runtime public-data refitting, then publishes the exact retained wheel
and source archive with installed-check evidence, commit manifest and checksums.
Prior versions and their assets remain available.
