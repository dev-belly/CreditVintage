# CreditVintage 0.4.1

This patch delivers the snapshot calendar-boundary correction in a checked
wheel and source archive. Earlier releases and their assets remain available.

## Changes from 0.4.0

Snapshot maturity now compares elapsed calendar days rather than adding the
outcome/reporting horizon to the decision date. A valid application near
`date.max` can remain `not_mature` without raising `OverflowError`. Six boundary
regressions cover ages 0, 181 and 182 and invalid cutoff types. The public Python
`snapshot` API requires a calendar `date`; strings, `datetime` and `None` fail
through `DataContractError`, including for an empty population.

The 180-day outcome horizon, two-day reporting lag, complete-report requirement,
90+ DPD rule, model fitting, calibration, numerical dependency pins and replay
tolerances remain unchanged. Normal-calendar reports and existing input schemas
retain their protocols; there is no model migration or new predictive-performance
claim. Current monitoring outcomes remain unnecessary for monitoring preflight.

## Install or upgrade

In a Python 3.12+ virtual environment:

```text
python -m pip install --upgrade https://github.com/dev-belly/CreditVintage/releases/download/v0.4.1/creditvintage_research-0.4.1-py3-none-any.whl
python -c "from importlib.metadata import version; print(version('creditvintage-research'))"
python -m creditvintage preflight --as-of 2024-10-01
```

The version check prints `0.4.1`. The built-in synthetic monitoring preflight
requires mature historical train/calibration cohorts and visible current
applications; it does not fit a model, write reports or use current outcomes.
Use `.venv/bin/python` on Linux/macOS or `.\.venv\Scripts\python.exe` on Windows
for an environment named `.venv`.

The publisher waits for all main CI jobs, including clean installed-package
replay/refitting, the six snapshot calendar-boundary checks against the installed
wheel, and cross-runtime checks, then publishes the actual retained
distributions without rebuilding. The release has the source archive, wheel,
installed-check evidence, exact-commit manifest and SHA-256 checksum list.
Existing release files are not replaced.
