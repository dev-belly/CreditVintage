# CreditVintage 与同方向成熟项目的对照

核查日期：2026-10-26（本轮重新核对 scikit-learn 与 SBA 官方来源；其他框架沿用各自既有核查）。对照官方文档和当前源码，关注可以实际运行的能力。
这里没有把 Star 数、功能数量或自己的测试次数换算成项目水平。

CreditVintage 的范围是：把信贷数据的时间口径、模型对照、分数监控和人工复核
连接成一条可检查的本地流程。对金融数据分析、风控实习，先能解释清楚这条流程，
再根据真实输入补功能。

## 对照结果

| 对照项目 | 官方已公开的能力 | CreditVintage 已有的对应能力 | 仍然存在的差距 |
| --- | --- | --- | --- |
| [scikit-learn](https://scikit-learn.org/1.8/common_pitfalls.html#data-leakage) · [TimeSeriesSplit](https://scikit-learn.org/1.8/modules/generated/sklearn.model_selection.TimeSeriesSplit.html) | 先切分再拟合预处理；按时间切分，可设样本行数 gap | SBA 真实放款日期、24 日历月表现期、阶段间成熟间隔、训练集独占预处理、独立校准；保留全部方法与年份结果 | 固定协议的一次回溯研究，不是一般交叉验证/实验平台；没有历史首次发布与修订记录 |
| [Evidently](https://docs.evidentlyai.com/metrics/preset_data_summary) | 比较数据质量与列分布，可按参照集或自定义条件增加测试 | 原有 PSI 与五项输入分布；v0.6.0 补应检查事件槽位的时点覆盖率、逐月原因与可见迟到统计 | v0.7.0 支持三项覆盖率/最小样本规则；仍无任意列指标、监控服务或显著性判断 |
| [Great Expectations](https://docs.greatexpectations.io/docs/reference/learn/data_quality_use_cases/missingness/) | 按列约束非空值及其比例，支持明确容忍范围 | 当前诊断以申请与三项应检查特征为分母，保留不可用原因；严格评估入口仍拒绝缺失 | 可显式检查整体/指定月份覆盖并保留失败证据；仍无通用 Expectation、Checkpoint/Action 体系，事件缺席不同于单元格空值 |
| [TensorFlow Data Validation](https://www.tensorflow.org/tfx/data_validation/get_started) | 按 schema 检查特征存在性与异常，区分训练/服务环境及漂移/偏移 | 诊断与评分有独立目的；两者共享时点选择和身份校验，诊断可解释缺口，评分仍须完整 | 不支持 TFDV 的一般 schema 环境、统计类型与通用训练/服务偏移检查 |
| [scorecardpy](https://github.com/ShichenXie/scorecardpy/blob/master/README.md) | 变量筛选、WOE 分箱、评分卡缩放和评价函数 | 合成事件实验有训练集隔离的 WOE 对照；公开数据有固定基线与同容量比较 | 不是通用评分卡工具；事件接口只接受三个指定特征和两个客群，不能随意重命名业务字段来接入 |
| [Qlib](https://github.com/microsoft/qlib/blob/main/docs/component/workflow.rst) | 配置化数据、训练、评价工作流与实验产物跟踪 | 严格日期配置、三阶段隔离、冻结公开数据、保存切分与逐笔分数、安装包重放 | 研究范围窄；缺少大规模实验管理；已有 SBA 真实放款分期研究，但不是历史可得信息重建。Qlib 面向量化投资，其回测指标不能与本项目 AUC 直接比较 |
| [Feast](https://docs.feast.dev/getting-started/concepts/point-in-time-joins) | 历史特征按实体时间关联，并提供 TTL 和特征存储工作流 | 事件接口检查决策时可得特征；可选 PITBridge 把报告追到源记录与修订 | 不是特征平台；没有在线特征服务、多种离线存储适配或部署验证 |

这些项目解决的问题各不相同。上表是能力与范围对照，没有运行它们的统一性能
基准，也没有得出 CreditVintage 胜过其中任何一个的结论。

## 本轮实做：真实日期、原生目标与离线重拟合

v0.8.0 从两份完整官方 SBA CSV 的 1,236,084 条记录中，按预定日期、
记录身份分组和不使用结果的 SHA256 优先级形成 35,000 条样本。
20,000/5,000/10,000 三阶段的表现期互不越过下一阶段开始时间。
测试集 89 个记录内事件；逻辑回归 AUC 0.6723，校准后 AUC 0.6584，
Brier 从 0.009011 降到 0.008819，较差排名保留。相同 1,000 个复核名额
分别找到 26/89、24/89 个事件，不能换算成避免损失。

安装包内置来源/协议/转换审计，保留全年份、全部预测及 300 次成对月份
重采样；核验从来源重拟合，重新计算哈希的虚假 AUC 仍失败。
[完整协议](SBA_CREDIT.md) · [在线报告](https://dev-belly.github.io/CreditVintage/sba-credit/)。
已补真实放款日期跨期验证；最终快照没有历史首次发布/特征修订记录，
所以没有把它说成真实历史公开信息的时点回放。

## 已完成的监控路径与试用入口

v0.7.0 增加[显式覆盖率规则](FEATURE_POLICY.md)：使用者指定人群、整体或月份、
特征、最小申请数与最低覆盖比例。规则按整数计数精确判断，小/空人群为证据不足；
失败和不足都返回退出码 3，并保留可重建的来源、规则和逐项判定。报告核验返回 0
只表示证据一致，会单独显示策略失败。外部保存的策略摘要可以拒绝完整重建后的
规则替换；来源真假仍未被认证，宽松或部分规则通过也不等于评分就绪。

这里借鉴 [Evidently 条件测试](https://docs.evidentlyai.com/docs/library/tests)
以及 [GX 验证结果与后续步骤](https://docs.greatexpectations.io/docs/core/trigger_actions_based_on_results/create_a_checkpoint_with_actions/)
将描述性统计和验收条件分开。新检查只覆盖固定三项时点特征，不实现任意规则、
自动阈值、消息动作或服务平台；没有据此声称复刻或超越上述框架。

v0.6.0 增加 [时点覆盖率与可见迟到诊断](FEATURE_QUALITY.md)：只读两张事件表，
为每笔可见申请保留三个应检查槽位，区分当时可用、已知迟到、决策后才观测到及
截至报告日无可见记录。报告日之后的记录不会用于解释过去。迟到使用首次到达时间，
小月份保留计数，空人群的覆盖率为 null；没有把未知延迟补零或把不完整申请移出分母。

这里借鉴的是成熟工具把数据质量与分布变化分开检查的工作流。新指标针对固定事件
契约，并未把事件缺席等同于原始 CSV 单元格空值；也没有声称胜过这些工具或运行
它们的统一性能对照。诊断报告能完整生成，并不意味着数据已经满足评分条件。

v0.5.0 新增 [不读取任何标签的输入分布检查](FEATURE_MONITORING.md)：
`monitor-features` 只读申请与特征事件两张表，以历史校准窗口为参照，检查授信使用率、
负债收入比、历史逾期次数、申请金额与客群构成。它复用原 `snapshot` 的决策时可得性
选择；保存原始事件、所选快照、累计计数及页面，`verify-feature-monitor` 可以重建核验。
数值距离经手算案例和 SciPy 两样本 KS 独立实现核对。小于 20 条的月度样本不输出距离，
不设置自动告警阈值，不把分布变化解释为违约变多或模型失效。

这补上了“只能看总分、难以追问哪个输入变化”的一部分差距。分布检查仍由严格契约
拒绝缺失；覆盖、可见迟到与显式规则另走独立路径，仍没有真实跨期业务采纳证据。与下面的分数监控相比，
这条新路径连历史标签也不需要；旧的 `monitor` 仍需要成熟历史标签来拟合模型。

此前 `preflight` 检查的是完整成熟评估，因此当前贷款没有结果标签时会失败。
但 `monitor` 本身允许这种输入。两条入口的用途不同，容易让首次接入者误以为
数据完全不可用。

从 0.4.0 起：

- `preflight --as-of YYYY-MM-DD` 检查监控输入，不训练、不生成报告。
- 历史训练和校准仍要求完整成熟标签、两类结果和至少 20 条样本。
- 当前队列只要求至少 20 条已可见申请及决策时可用特征，不要求结果标签。
- JSON 分开列出已可见当前申请、尚不可见当前申请和窗口外申请；不输出当前
  事件数、分数或 PSI。
- 预检和实际监控共用当前样本筛选，预检和拟合共用历史样本筛选。当前样本不足
  会在拟合之前失败。
- 安装包检查也覆盖这条路径，防止源码能跑、下载的 wheel 缺少命令或资源。

监控预检已在 [#28](https://github.com/dev-belly/CreditVintage/pull/28) 合入主分支。
本次补充[无当前标签示例](../examples/monitoring_without_outcomes.py)、直接复跑命令
及跨平台示例检查：生成可编辑 CSV，移除当前结果，保存预检结果并生成可核验报告。
示例在当前源码中；已构建的 v0.4.0 安装包保持原样。示例使用的监控 API 和命令
属于 v0.4.0，可在安装该版本后运行当前源码里的示例文件。

运行入口见[接入说明](CUSTOM_INPUTS.md#4-before-outcomes-mature)，接口与升级说明见
[0.4.0 发行说明](releases/v0.4.0.md)。预检通过只表示输入和样本口径就绪；
实际拟合、参考分数是否有变化、未来效果仍需后续检查。

## 旧差距中已经补齐的部分

| 原来的问题 | 当前能核查的事实 | 不能据此声称的事 |
| --- | --- | --- |
| 只有小规模合成数据 | 单独保留 1,000 条德国信贷与 30,000 条信用卡公开观察数据；信用卡实验保留五组切分、四个方法和 60 组同预算比较 | 随机客户切分不能验证真实历史时点或未来表现 |
| 缺少明确代码授权 | 根目录 MIT；UCI 保留 CC BY 4.0，SBA 保留 U.S. Government Works 来源说明 | 数据许可不代表有真实银行部署授权 |
| 没有可下载安装包 | 已有受检的 v0.6.0；v0.7.0 按完整 CI 门槛发布显式覆盖规则，旧版本保留 | 源码与实际发行状态分别以提交和 Releases 为准，分支代码不等于已发布的 wheel |
| 安装后能否复现不清楚 | CI 在源码之外安装 wheel；Linux/Windows、Python 3.12/3.13 按矩阵重算证据 | 自动化安装检查不是外部用户采用记录 |

下一轮最有价值的输入是一次真实试用记录，或一份满足时间契约的数据来源。
