# CreditVintage 与同方向成熟项目的对照

核查日期：2026-10-23。对照官方文档和当前源码，关注可以实际运行的能力。
这里没有把 Star 数、功能数量或自己的测试次数换算成项目水平。

CreditVintage 的范围是：把信贷数据的时间口径、模型对照、分数监控和人工复核
连接成一条可检查的本地流程。对金融数据分析、风控实习，先能解释清楚这条流程，
再根据真实输入补功能。

## 对照结果

| 对照项目 | 官方已公开的能力 | CreditVintage 已有的对应能力 | 仍然存在的差距 |
| --- | --- | --- | --- |
| [Evidently](https://docs.evidentlyai.com/metrics/explainer_drift) | 比较参考集与当前集的特征、预测或目标分布，按列类型配置方法；缺失率另做质量检查 | 无当前结果标签的分数 PSI；固定参考分箱；逐月样本量和分箱贡献；可独立重算报告 | 目前只监控模型分数，缺少逐特征漂移、缺失率趋势与可配置检查组合；没有监控服务 |
| [scorecardpy](https://github.com/ShichenXie/scorecardpy/blob/master/README.md) | 变量筛选、WOE 分箱、评分卡缩放和评价函数 | 合成事件实验有训练集隔离的 WOE 对照；公开数据有固定基线与同容量比较 | 不是通用评分卡工具；事件接口只接受三个指定特征和两个客群，不能随意重命名业务字段来接入 |
| [Qlib](https://github.com/microsoft/qlib/blob/main/docs/component/workflow.rst) | 配置化数据、训练、评价工作流与实验产物跟踪 | 严格日期配置、三阶段隔离、冻结公开数据、保存切分与逐笔分数、安装包重放 | 研究范围窄；缺少大规模实验管理和真实跨期信贷验证。Qlib 面向量化投资，其回测指标不能与本项目 AUC 直接比较 |
| [Feast](https://docs.feast.dev/getting-started/concepts/point-in-time-joins) | 历史特征按实体时间关联，并提供 TTL 和特征存储工作流 | 事件接口检查决策时可得特征；可选 PITBridge 把报告追到源记录与修订 | 不是特征平台；没有在线特征服务、多种离线存储适配或部署验证 |

这些项目解决的问题各不相同。上表是能力与范围对照，没有运行它们的统一性能
基准，也没有得出 CreditVintage 胜过其中任何一个的结论。

## 已完成的监控路径与这次的试用补充

此前 `preflight` 检查的是完整成熟评估，因此当前贷款没有结果标签时会失败。
但 `monitor` 本身允许这种输入。两条入口的用途不同，容易让首次接入者误以为
数据完全不可用。

从 0.4.0 起：

- `preflight --as-of YYYY-MM-DD` 检查监控输入，不训练、不生成报告。
- 历史训练和校准仍要求完整成熟标签、两类结果和至少 20 条样本。
- 当前队列只要求至少 20 条已可见申请及决策时可用特征，不要求结果标签。
- JSON 分开列出已可见当前申请、尚不可见当前申请和窗口外申请；不输出当前
  事件数、分数或 PSI。
- 预检和实际监控共用当前样本筛选，预检和拟合共用历史样本筛选。当前样本不足
  会在拟合之前失败。
- 安装包检查也覆盖这条路径，防止源码能跑、下载的 wheel 缺少命令或资源。

监控预检已在 [#28](https://github.com/dev-belly/CreditVintage/pull/28) 合入主分支。
本次补充[无当前标签示例](../examples/monitoring_without_outcomes.py)、直接复跑命令
及跨平台示例检查：生成可编辑 CSV，移除当前结果，保存预检结果并生成可核验报告。
示例在当前源码中；已构建的 v0.4.0 安装包保持原样。示例使用的监控 API 和命令
属于 v0.4.0，可在安装该版本后运行当前源码里的示例文件。

运行入口见[接入说明](CUSTOM_INPUTS.md#4-before-outcomes-mature)，接口与升级说明见
[0.4.0 发行说明](releases/v0.4.0.md)。预检通过只表示输入和样本口径就绪；
实际拟合、参考分数是否有变化、未来效果仍需后续检查。

## 旧差距中已经补齐的部分

| 原来的问题 | 当前能核查的事实 | 不能据此声称的事 |
| --- | --- | --- |
| 只有小规模合成数据 | 单独保留 1,000 条德国信贷与 30,000 条信用卡公开观察数据；信用卡实验保留五组切分、四个方法和 60 组同预算比较 | 随机客户切分不能验证真实历史时点或未来表现 |
| 缺少明确代码授权 | 根目录 MIT；随包数据保留各自 CC BY 4.0 归属和来源 | 数据许可不代表有真实银行部署授权 |
| 没有可下载安装包 | 已发布 v0.3.2；监控预检在主分支 v0.4.0，按既有检查流程发布并保留旧版本 | 源码示例与已构建的发行包分别标明，分支代码不等于已发布的 wheel |
| 安装后能否复现不清楚 | CI 在源码之外安装 wheel；Linux/Windows、Python 3.12/3.13 按矩阵重算证据 | 自动化安装检查不是外部用户采用记录 |

## 接下来仍需要的证据

| 优先项 | 完成它需要什么 | 当前状态 |
| --- | --- | --- |
| 真实跨期验证 | 有来源许可、申请/放款时间、表现期和信息可得记录的数据；按时间切分，同预算比较并保留失败结果 | 公开静态实验和合成事件实验都不能替代；本次没有补造时间字段 |
| 特征与数据质量监控 | 有业务含义的字段契约，逐特征分布与缺失/延迟指标，并明确样本量和比较范围 | 当前严格输入会拒绝缺失特征；尚未实现缺失率趋势或通用漂移检查 |
| 更多输入适配 | 至少一个来源清楚、字段含义匹配的新业务样例，以及转换前后核验 | 当前三个特征的严格事件契约保留；不伪装成任意 CSV 都能接入 |
| 独立试用 | 另一位使用者从空环境按说明完成一次任务，记录命令、失败点和反馈 | 本地示例及 CI 已覆盖可运行路径，尚未核实独立使用者或客户部署 |
| 作者能亲自讲清楚 | 运行无标签例子，解释为何训练仍需标签、80 与 40 的分界、为何 PSI 不能证明预测变差 | 代码和文档提供练习材料；不替作者声称已经掌握 |

下一轮最有价值的输入是一次真实试用记录，或一份满足时间契约的数据来源。
没有这些证据时，继续增加模型种类和仓库数量不能补上表中的空缺。
